# CS 305: Software Security

Artemis Financial was the financial services client for this project. The company needed to protect sensitive customer information by improving the security of its software and communications. I refactored its Java Spring application to generate SHA-256 checksums and use HTTPS. I did well at separating the purpose of each security measure and checking that it worked. Hashing helps detect changes when a checksum is compared with a trusted original, while HTTPS encrypts communication. Secure coding helps a company protect customer information, maintain trust, and reduce the risk of breaches, downtime, and costly repairs. Reviewing the dependency scan was especially helpful because it showed that an application can build and run successfully while still containing vulnerable libraries.

I added layers of security through checksum generation, HTTPS with a locally generated self-signed certificate, and an environment variable that kept the keystore password outside the source code. To check functionality and security after refactoring, I manually reviewed the changed code and configuration, ran Maven testing, verified the endpoint over HTTPS in Chrome, and compared its checksum with an independent SHA-256 calculation. I also ran OWASP Dependency-Check to identify library vulnerabilities. The scan still flagged existing vulnerable dependencies, which I documented in the report. These checks supported the changes I made, but did not prove the entire application was free of vulnerabilities. In future projects, I would combine dependency scanning, manual code review, and threat modeling, then choose fixes based on the likelihood and impact of each issue. Java’s built-in cryptographic tools, Keytool, Maven, OWASP guidance, and keeping secrets outside source code are practices I can reuse. I would show future employers my Practices for Secure Software Report to demonstrate how I implemented security measures, tested the results, and documented remaining risks.
